# 本地性能与故障验证

这份结果来自 `benchmarks/` 中的可重复运行程序，用于说明 JoeyRPC 在指定本机条件下的行为。它不是生产环境容量、跨机器延迟或与其他 RPC 框架的性能对比。

## 环境与运行方式

- 采集日期：2026-10-05。
- Windows/amd64，Go 1.26.4，16 个逻辑 CPU；单进程内启动客户端和服务端，通过 `127.0.0.1` 的 TCP 回环连接通信，使用 Gob 编解码。
- Echo 请求携带 64 KiB 字节数据，响应回传同样的数据；每次调用都检查响应内容。服务方法只复制数据，不访问数据库或外部服务。
- 每轮先进行 100 次不计入统计的预热调用，再进行正式测量。下面的相同命令连续运行 3 次，原始输出保存在 [`benchmarks/results/local-2026-10-05.json`](../benchmarks/results/local-2026-10-05.json)。

```sh
go run ./benchmarks -requests 3000 -concurrency 16 -payload 65536 -warmup 100 -reuse-samples 200 -failover-samples 50 -inflight 20
```

程序在 Windows 上使用 `QueryPerformanceCounter` 测量单次延迟，其他平台使用 Go 单调时钟。P50/P95 从每次调用的耗时样本中按最近秩计算；QPS 等于完成调用数除以整段测量时间。`go run` 的编译时间不计入这些指标。

## 结果

**单连接并发调用：**16 个调用 goroutine 共享一条 TCP 连接，每轮完成 3,000 次请求。

| 轮次 | QPS | P50 | P95 |
| --- | ---: | ---: | ---: |
| 1 | 7,167 | 2.151 ms | 2.917 ms |
| 2 | 7,028 | 2.172 ms | 2.998 ms |
| 3 | 6,420 | 2.341 ms | 3.342 ms |
| 三轮中位数 | **7,028** | **2.172 ms** | **2.998 ms** |

**连接复用：**每轮两种方式各执行 200 次顺序调用。新建模式计入 `Dial → Call → Close` 的完整耗时；复用模式先建一条连接，再只测 `Call`。这是建连开销的对照，两个数字的计时范围不同。

| 轮次 | 每次建连 P50 | 复用 P50 | 每次建连 P95 | 复用 P95 | TCP 连接数 |
| --- | ---: | ---: | ---: | ---: | --- |
| 1 | 0.830 ms | 0.253 ms | 1.324 ms | 0.525 ms | 200 vs 1 |
| 2 | 0.816 ms | 0.280 ms | 1.355 ms | 0.540 ms | 200 vs 1 |
| 3 | 0.965 ms | 0.312 ms | 1.708 ms | 0.673 ms | 200 vs 1 |
| 三轮中位数 | **0.830 ms** | **0.280 ms** | **1.355 ms** | **0.540 ms** | **200 vs 1** |

**故障与关闭：**程序先启动两个 RPC 节点，再关闭其中一个；发现接口仍首先返回已退出节点的地址，备用节点保持在线。每轮不启用重试的 50 次调用全部失败；开启最多 2 次尝试和 10 ms 初始退避后，50 次调用全部经备用节点成功，三轮合计为 **150/150**。这个场景验证的是**发送请求之前的建连失败与切换**，没有测量请求已经发出后的连接中断、业务幂等性或整个集群的故障恢复时间。

每轮另有 20 个请求在服务端方法中等待。确认它们全部进入方法后发起 `Shutdown`，故意保持 100 ms 不释放；关闭操作没有提前返回。释放后，20 个方法和 20 个客户端调用均成功完成，三轮合计 **60/60**。约 101 ms 的关闭耗时主要来自人为保持的 100 ms，不能作为服务端关闭开销引用。

## 使用这些数字时

可以准确表述为“在本机 TCP 回环、64 KiB 请求/响应、16 并发的测试中，三轮测得约 7,028 QPS，P50 约 2.17 ms、P95 约 3.00 ms；连接复用降低了同机顺序调用的建连开销”。不要把它写成生产环境吞吐或真实遗留系统接入效果。不同机器、请求大小、网络距离和业务方法都会改变这些值。
