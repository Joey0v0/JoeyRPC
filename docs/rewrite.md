# JoeyRPC 实现重写记录

本轮逐目录检查后，按已有公开接口重新组织内部实现，随后将 HTTP 协议名称统一为 JoeyRPC。重写前的源码留存在工作区外，用于本地接口对比及命名调整前的新旧版本互通验证；旧实现没有作为第二套运行库加入当前工程。

## 保持的行为契约

- 模块路径与根包名保持不变，公开函数、接口、导出类型及导出字段的名称和类型保持一致。
- `Method(args, replyPointer) error` 的注册约定、`Service.Method` 寻址和 `Seq` 响应匹配保持不变。
- JSON `Option`、Gob 消息头与正文保持不变。HTTP 路径、CONNECT 状态文本及注册请求头已统一为 JoeyRPC，使用旧 HTTP 名称的组件需同步升级。
- 默认连接超时 10 秒、处理超时 0、实例有效期 5 分钟、心跳间隔 4 分钟、发现缓存 10 秒保持不变。
- 保留 TCP、HTTP CONNECT、Unix Socket 寻址、同步/异步调用、随机/轮询选择、连接复用、广播与调试页面。
- 广播等待全部调用返回，写入第一个成功结果，记录第一个错误，并取消尚未完成调用的客户端等待。
- 心跳在首次注册成功后周期发送，遇到失败结束循环；未增加自动重试。
- 示例仍启动端口 9999 的注册中心和两个动态端口服务，演示相同的求和、广播、休眠与超时行为。

## 异常路径的修复

正常使用的功能保持兼容。以下原有缺陷进行了修复，因此这些异常场景的行为比旧实现更完整：

- 找不到服务或方法时，先消费该请求的正文，避免下一次请求错位。
- 返回错误字符串不再把 `%` 当格式指令解释。
- Gob 缓冲刷新失败会返回错误并关闭连接，不再误报写入成功。
- 处理超时后不再因无接收者的完成通知永久阻塞；连接构造器迟到时会释放其客户端。
- 取消与正在进行的结果解码协调，避免返回后再修改调用方结果。
- 规范化配置时不再修改共享的调用方 `Option`；地址列表也复制后保存。
- 无效接收者注册返回错误，不再退出应用；非法方法签名被过滤；方法 panic 转为调用错误。
- 注册和发现关闭 HTTP 响应体，非成功状态返回错误；心跳循环退出时释放 ticker。
- HTTP/JSON 预读缓冲被保留；并发关闭时不会把迟到连接重新放入已清空的缓存。

这些修复没有新增服务发现协议、自动重试、按服务分组、流式调用或跨语言编码。

取消有一个明确的边界变化：若响应已开始解码，`Call` 会等待解码结束后再返回取消错误，而不是立刻返回并允许接收协程继续修改结果。context 因此不是严格的返回时间上限。

## 验证方式

仓库内保留重写前已有的测试，并新增真实网络和可控传输的边界测试。标准命令：

```sh
go test -count=1 -timeout=45s ./...
go vet ./...
go run ./examples/registry
```

HTTP 名称调整前，本地另用 Go AST 对比公开接口清单，并在独立消费项目中分别运行旧客户端/新服务端、新客户端/旧服务端的 TCP 和 HTTP 调用，以及注册发现的双向交叉验证。这些结果用于验证实现重写，不代表命名调整后的 HTTP 组件仍兼容旧版本。

本轮实际验证结果：

- 原有测试及新增边界测试通过；`go vet ./...` 通过。
- `go test -cpu=1,4 -count=3 -timeout=90s ./...` 通过，覆盖不同并发调度下的重复运行。
- Windows 32 位（`GOARCH=386`）全部测试通过，验证原子计数的对齐要求。
- 68 项公开声明的接口清单一致；HTTP 命名调整前，TCP、HTTP、注册发现的五组新旧交叉测试通过。
- 完整注册中心示例运行通过，求和与广播输出正确，预期的休眠超时正常返回。
- 当前环境未配置 CGO/C 编译器，未运行 `-race`；Unix Socket 用例在 Windows 上跳过，Linux 运行尚未验证。

HTTP 命名统一后，已再次通过 `go test -count=1 -timeout=45s ./...`、`go vet ./...` 和完整注册中心示例。当前 HTTP 调用、调试页面、注册发现、心跳与广播均使用新的 JoeyRPC 名称；未保留旧 HTTP 名称的兼容别名。

实现重写基于已经阅读的项目，并保留已有版权与许可声明，不将重写程度作为删除第三方版权的依据。许可文档中的项目名称与仓库链接已精简，原作者版权行及完整许可正文没有更改。
